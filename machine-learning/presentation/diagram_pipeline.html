1) INTENT ROUTING — DETERMINISTIC, NO LLM One binary decision, in about two milliseconds
Faculty gazetteer Exact and fuzzy match against the roster of consented lecturers.
Intent lexicon Availability phrasing: free, in, available, consultation, meet.
Ambiguity check Two lecturers matched → return a clarifying question, never guess.
Why not an LLM router. A classification call costs 150–300 ms of the response-time budget this study has to report, on a decision a lookup answers in two. It is also non-deterministic, so the same query could route differently on two runs and no evaluation would be reproducible. The roster is a known, closed, small list — a gazetteer problem, not an open-ended NLU problem.

2) PARALLEL RESOLUTION Retrieval runs in BOTH architectures and is never conditional on the route. Only branch B distinguishes Enhanced from standard.
A · DOCUMENT BRANCHNO — standard and Enhanced alike
Embed the query all-MiniLM-L6-v2, 384 dimensions, L2-normalised — the same model that embedded the corpus.
Exact cosine over every chunk Top 5, similarity floor 0.25. No approximate index: at 232 chunks an exact scan takes ~170 ms and always returns the true nearest, where an ANN index would add a failure mode and save nothing.
This branch never crosses the mask Documents are not people. The masking protocol governs the status, not the passages.
